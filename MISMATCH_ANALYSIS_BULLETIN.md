# Анализ: почему `Бюллетень_17.2.8_ГОТОВЫЙ.docx` не совпадает с эталоном

## Что проверено
1. Сравнение структуры файлов показало, что в корне и в `output/` лежат **разные** документы с одинаковым именем.
2. Сравнение `output/Бюллетень_17.2.8_ГОТОВЫЙ.docx` и `output/как должно быть!.docx` по таблицам/ячейкам.
3. Проверка шаблона `output/Бюллетень_ШАБЛОН_С_ТЕГАМИ_v2.docx` на корректность расстановки тегов.
4. Анализ логики маппинга столбцов в `logic.py`.

## Ключевые выводы

### 1) Частая причина «полного несовпадения» — сравнивается не тот файл
- `./Бюллетень_17.2.8_ГОТОВЫЙ.docx` (в корне) содержит только **1 таблицу** и очень маленький объём текста.
- `./output/Бюллетень_17.2.8_ГОТОВЫЙ.docx` содержит **19 таблиц** и является результатом пайплайна из `main.py`.

Это означает, что если сравнивать корневой файл с эталоном, несовпадение гарантировано уже из-за неверного артефакта.

### 2) Даже «правильный» файл из `output/` сейчас всё равно расходится с эталоном
- По ячейкам найдено **1057 различий**.
- Самые проблемные таблицы: **8, 5, 14, 17, 16, 15**.

### 3) Главная техническая причина: неверная расстановка тегов в шаблоне для многоуровневых заголовков
В шаблоне часто один и тот же тег дублируется в нескольких столбцах одной строки (вместо разных показателей).

Пример (таблица 5):
- В строке с данными один и тот же `VneObAk` ставится сразу в 3 пар столбцов 2022/2023.
- В результате в готовом документе одинаковые числа повторяются там, где в эталоне должны быть разные показатели (например, «внеоборотные активы», «НМА», «основные средства»).

Пример (таблица 8):
- `ObAkObr` повторяется для столбцов «запасы», «НДС», «дебиторская задолженность».

Пример (таблица 17):
- Для части столбцов повторно подставляется `OtlNalOb` вместо отдельного показателя `OcObDl`.

### 4) Почему это происходит в коде
В `logic.py` маппинг строится по **одной** строке `indicator_row` + строке `year_row`, с переносом `current_indicator` на пустые/соседние ячейки.
Для сложных таблиц, где показатель формируется из нескольких строк заголовка, это приводит к «растеканию» одного индикатора на несколько разных подколонок.

## Что исправить в первую очередь
1. Сравнивать эталон только с `output/Бюллетень_17.2.8_ГОТОВЫЙ.docx`.
2. Переделать построение `col_to_indicator_map` в `generate_word_template()`:
   - учитывать несколько строк заголовка (иерархию),
   - собирать «полный путь заголовка» по столбцу,
   - матчить индикатор по составному заголовку, а не по одной строке.
3. Добавить валидацию шаблона:
   - проверка на дубли тегов в одной строке данных,
   - fail-fast, если в строке несколько разных подколонок получили один и тот же indicator code.
4. Для таблиц 5/8/14/17 сделать targeted regression-тесты на ожидаемые коды индикаторов по столбцам.
