## 🔍 НАЙДЕННЫЕ ПРОБЛЕМЫ

### 1️⃣ КРИТИЧЕСКАЯ: Рассинхронизация формата тегов

**Проблема:**
- [logic.py](logic.py) генерирует теги: `{{OKVED_50_13_11_ValBal_22}}`
- [data_filler.py](data_filler.py) пытался парсить их неправильно:
  ```python
  indicator, code = tag.split("_", 1)  # НЕПРАВИЛЬНО!
  # {{OKVED_50_13_11_ValBal_22}} разбивалось как:
  # indicator = "OKVED"
  # code = "50_13_11_ValBal_22"  ❌ НЕПРАВИЛЬНО!
  ```

**Решение:**
Переписана функция `fill_word_template_by_tags()` для правильного парсинга:
```python
# Теперь правильно парсим:
parts = full_tag.split("_")
year_suffix = parts[-1]          # "22"
indicator = parts[-2]            # "ValBal"  
okved_parts = parts[1:-2]        # ["50", "13", "11"]
okved_code = ".".join(okved_parts)  # "50.13.11"
```

### 3️⃣ КРИТИЧЕСКАЯ: Неправильная логика парсинга в старом коде

**Проблема:**
Старый код в [data_filler.py](data_filler.py) неправильно разбивал теги:
```python
matches = extract_tags(run.text)
for tag in matches:
    indicator, code = tag.split("_", 1)  # ❌ РАЗБИВАЕТСЯ НЕКОРРЕКТНО
    # Если тег: "ValBal_50_13_11_22"
    # Получается: indicator="ValBal", code="50_13_11_22"  ❌ НЕПРАВИЛЬНО!
```

**Решение:**
Переписана логика парсинга с использованием регулярного выражения и правильного разбора:
```python
tag_regex = re.compile(r"\{\{(OKVED[_A-Za-z0-9]+)\}\}")
# Теперь ищет теги вида: {{OKVED_50_13_11_ValBal_22}}
# И корректно их разбирает
```
